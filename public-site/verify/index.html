Local verification

Verify a passage.

Give Lean a recording of the keys you pressed. It replays each input and proves when the first exit occurred, together with the player's exact final state.

Python 3.9+ · Lean 4.33.0 · macOS, Linux or a suitable Lean environment

Check the first room

Save the ZIP and its checksum in the same directory. Check the archive, unpack it, and run the included example. Install elan first if your computer does not have it. Install Lean.

shasum -a 256 -c lean-doom-companion.sha256
unzip lean-doom-companion.zip
cd lean-doom-companion
elan toolchain install leanprover/lean4:v4.33.0
python3 verify.py check examples/prooflab-first-room.json

After 19 inputs, the first safe exit is true. The endpoint is at (13, 5), facing east, with 3 health, a blue key and an open bulkhead. The terminal prints a kernel-passage receipt. Read the checked L01 direct result · Read the route proofs.

Pair a recording folder

From the extracted kit, start the watcher. Then open the training course, choose Pair local Lean, and grant access to this same folder. Open the training course.

mkdir -p paired-runs
python3 verify.py watch paired-runs

Take control and reach the exit, or choose Save input tape to check an unfinished attempt. The watcher reads files named prooflab-*.json. A paired page displays the returned receipt automatically.

In browsers without directory pairing, save the tape into the watched folder and read the result in the terminal. A single recording can also be checked with python3 verify.py check /path/to/run.json.

Record the Lean port

For a CombatV2 tape, supply the same local IWAD used to play. The player lists complete Doom-format maps in episodes one through four, including Freedoom: Phase 1 and maps in your legally obtained Doom IWAD. Lake needs a working C toolchain. Native player instructions.

(cd combat && lake build map-player)
python3 play.py /path/to/your.wad

In a second terminal, from the extracted kit, start the watcher with the IWAD. Pair its folder in the native player.

mkdir -p paired-runs
python3 verify.py watch paired-runs --iwad /path/to/your.wad

Read the certificate

The result is saved beside the recording under .proofs/<file-sha256>/receipt.json. The receipt names an attempt directory with Inputs.lean, Certificate.lean and the fresh import in Audit.lean.

The first declaration decides whether every strict prefix stays alive and exit-free, with the exit at the last input. CombatV2 also checks each prefix for physics errors. The second declaration proves the coordinates, health and other final observations.

The recording hash binds the exact JSON bytes. CombatV2 also records the IWAD hash. Inspect the native run receipts · Read the training rules.

Give the job to an agent.

Open the extracted kit as the agent's project. It includes verify-doom-run in both .agents/skills/ and .claude/skills/. Choose a task, replace any example paths, and paste the prompt into your agent.

What the status means

kernel-passage
The stock Lean kernel checked the first-safe-exit and final-state declarations using decide +kernel. This is the training model's default.
compiler-passage
Lean accepted the declarations using native_decide, which adds compiler trust. This is CombatV2's default. Its receipt lists the axiom used by each declaration. To request strict reduction explicitly, pass --trust kernel.
kernel-prefix
compiler-prefix
The exact final observation was checked, and the predicate “first safe exit on the last input” was proved false. The prefix records the trust method used.
rejected
Read the diagnostic in the receipt. The supplied tape or its claimed observation failed validation, or compilation did not complete.
