What it means to vary the RNG

Doom’s gameplay RNG has a table of 256 bytes and a cursor. Getting the next byte increments the cursor, wraps at 256, and reads the corresponding entry. Presentation has a separate cursor. Spawning enemies and initializing lighting can consume gameplay draws. Original Doom RNG · Lean implementation

Load the map and perform ordinary combat spawn. Call that state ss. Construct sis_i by replacing only the post-spawn gameplay cursor with byte ii. Enemy states, the presentation cursor, inventory and geometry retain their values from ss. A seed supplied before spawn would be a different experiment. The baseline index is the gameplay cursor already in ss. Replacing that field by its own value recovers the ordinary state.

For fixed controls uu, let W(i)W(i) mean a safe exit on the tape from sis_i. One recording proves W(i0)W(i_0). To establish ∀i,W(i)\forall i, W(i) we must cover every byte. A failure supplies a counterexample to this controller’s robustness. A different controller could still win. Counting the winning indices gives an exact frequency in this finite family. Calling that frequency a probability requires a distribution on starting indices.

Another argument requires no enumeration. Insert any finite number of presentation draws before each gameplay draw. Each inserted draw preserves the gameplay cursor. Induct on the list of gaps. The first gap preserves the cursor, the next gameplay byte is the usual one, and the induction hypothesis gives every remaining byte. Stock Lean checked the histogram without axioms. The separate induction theorem uses Lean’s standard propositional extensionality axiom. This covers the same sequence of gameplay requests. Changing the game state can change which requests it makes.
